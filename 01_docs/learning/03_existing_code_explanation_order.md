# 03_existing_code_explanation_order

- 日付: 2026-08-24
- 関連: [02_effective_learning_flow.md](02_effective_learning_flow.md)（学習の5原則）・CLAUDE.md「実装作業の説明順序」（新規実装の提案用）
- 位置づけ: CLAUDE.mdの「実装作業の説明順序」は**これから作るもの**の説明用。こちらは**既にあるコードを理解したい時**の説明順序。`converter.py`/`orchestrator.py`の解説が「情報過多・専門用語が難しい」と感じられたことをきっかけに整理した。

## 背景

既存コードを解説した際、2ファイル分をコードの行から説明してしまい、情報量過多・専門用語（純粋関数、動的import等）の壁で理解できなかった。

## 決めた順番

```text
1. 一言で正体（専門用語なし）
   例：「これはPlantUMLの文章を、実行できる形に変換する係だよ」

2. たとえ話で全体像をつかむ
   例：「翻訳者みたいなもの。日本語（PlantUML）を、Pythonが分かる言葉（dict）に訳してるだけ」

3. 専門用語が出た瞬間、その場で平易に言い換える
   例：「正規表現」を使う前に「文字のパターン探しの道具」と言う

4. 具体例を1つだけ、最初から最後まで追う（コードは最小限）
   例：":カメラ画像撮影;" という1行だけを実際に手で追ってみる

5. ここで一旦止まって「ここまで大丈夫？」と聞く

6. 大丈夫なら次のトピックへ。1ターンに1つのファイル・1つの話題だけ
```

## 新規実装の説明順序との違い

| | 新規実装の説明順序（CLAUDE.md） | 既存コードの解説順序（ここ） |
|---|---|---|
| 対象 | これから作るもの | 既にあるコード |
| 起点 | 設計全体像→実装箇所 | 一言の正体→たとえ話 |
| 専門用語 | ある程度前提にして良い | 出た瞬間その場で言い換える |
| 単位 | 1機能ごと | 1ファイル・1話題ごと（さらに小さい） |
